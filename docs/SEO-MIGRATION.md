# SEO MIGRATION & REDESIGN PRESERVATION

> **MANDATORY GATE:** If the client has an existing live website, do not begin a redesign/build until the existing site's SEO footprint has been reviewed.

## Goal

Protect existing organic visibility while improving the website.

A redesign must not casually destroy URLs, content, internal links, metadata, schema, or search intent that may already be earning impressions, clicks, links, or rankings.

## 1. Inventory the Existing Site

Identify meaningful existing URLs, including:
- homepage
- service pages
- location/service-area pages
- about/contact pages
- blog/resources
- galleries/projects
- FAQs
- landing pages
- other indexable pages

For important pages record:
- current URL
- page purpose
- title tag
- H1
- primary topic/search intent
- meaningful content/topics
- important internal links
- canonical
- schema
- status/indexability

Use sitemap, crawl/navigation, Google results, and other available public sources.

## 2. Use Search Data When Available

If Google Search Console data is available, use it to identify:
- pages receiving clicks
- pages receiving impressions
- queries associated with pages
- pages with meaningful average positions
- pages that may have opportunity despite low clicks

Analytics and backlink data may also be useful when available.

Do not assume a page has no SEO value merely because it looks outdated.

## 3. Classify Every Meaningful Existing URL

Assign one action:

### PRESERVE
Keep the same URL and preserve its search intent. Improve design, UX, conversion, copy, and technical implementation without unnecessarily changing what the page successfully targets.

### IMPROVE
Keep the URL while substantially improving weak/thin/outdated content, structure, conversion, and SEO.

### CONSOLIDATE
Merge overlapping pages only when there is a clear strategic reason. Select the strongest destination and redirect retired URLs appropriately.

### REDIRECT
If a URL genuinely must change, create a permanent 301 redirect from the old URL to the closest relevant replacement.

### REMOVE
Only remove a page without replacement when it has no meaningful user/search value and no appropriate destination. Avoid redirecting unrelated pages to the homepage merely to avoid a 404.

## 4. URL Preservation Rule

**Do not change an existing valuable URL merely because a new URL structure looks cleaner.**

Preserve ranking/indexed URLs whenever practical.

When changing a URL:
OLD URL -> 301 -> most relevant NEW URL

Avoid:
- redirect chains
- redirect loops
- mass redirects to homepage
- unnecessary slug changes

## 5. Content Preservation Rule

A redesign is not permission to erase useful content.

When replacing an existing page, preserve or improve:
- search intent
- important topical coverage
- useful FAQs
- unique local/business information
- proof/trust elements
- meaningful internal links
- relevant structured data

Do not replace a substantive ranking page with a visually attractive but thin page.

## 6. Technical Preservation

Before launch verify:
- canonical URLs
- indexability
- robots directives
- XML sitemap
- metadata
- schema
- internal links
- 301 redirect map
- no accidental noindex
- no staging-domain canonicals
- no broken high-value URLs

## 7. Create a Client Migration Plan

For each existing-site redesign, create:

`context/SEO-MIGRATION-PLAN.md`

Recommended table:

| Existing URL | Purpose / Intent | Evidence / SEO Value | New URL | Action | Notes |
|---|---|---|---|---|---|
| /example/ | Service page | GSC impressions / indexed | /example/ | PRESERVE + IMPROVE | Keep intent |

## 8. Post-Launch

After launch:
- verify redirects
- verify important URLs return expected status
- submit/verify sitemap where appropriate
- inspect important pages in Search Console when access is available
- monitor indexing and organic performance for unexpected losses

## Core Rule

**Protect what already works before trying to improve it.**
